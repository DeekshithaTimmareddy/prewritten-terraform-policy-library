# Ensure That the Log Metric Filter and Alerts Exist for VPC Network Changes

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging and monitoring |

## Description

This control checks for a `gce_network` log metric covering the five VPC operations: insert, patch, delete, remove peering, and add peering. The methods must be OR alternatives. The metric must be referenced by an enabled alert policy condition threshold with at least one notification channel.

The policy accepts the console filter form and the documented CLI method prefixes. The Google provider defaults an omitted or null `enabled` value to true; an explicitly disabled alert does not qualify. Notification channel suitability and alert thresholds are organization-specific and are not evaluated.

Metrics with an empty filter, a `gce_network` reference, or a `compute.networks.` operation are candidates for this control. Unrelated metrics and alerts are outside its resource checks. A plan with no network-related metric cannot prove that the required metric exists, because there is no candidate resource to evaluate.

The `network-change-alert-enforcement-level` input controls both resource policies and defaults to `advisory`.

This rule is covered by the [2-10-network-change-alert](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/logging/2-10-network-change-alert.policy.hcl) policy.
